# Act I — три сюжета, одна камера

## Цель

Цельный **Акт I** для каждого происхождения (свидетель / еретик / полый) с:
- скрытой **главной линией** (названия шагов открываются по мере игры);
- **опциональными** задачами (печать, Синод, маска, провал);
- обязательными **флагами** и условиями (живые извлечения, глубина, встречи);
- уникальными **сценами** и приоритетом в пуле директора.

Акт завершается сценой-финале происхождения + флаг `act1_{origin}_complete`. Акт II — отдельная фаза позже.

## Общая структура петли

1. Камера → обет (опционально) → спуск.
2. На спуске: сцены акта всплывают, когда активен шаг квеста.
3. Возврат (любой исход) → прогресс квеста пересчитывается → эхо / журнал / телега.
4. В хронике вкладка **«Акт I»**: главная цепочка + опциональные задачи.

## Сцены акта (по 4 на происхождение)

Вплетены в `choicePools` / `boostPoolForActQuest` при активном шаге.

## Техническая модель

- `HubState.act1`: `{ completedStepIds, revealedStepIds, finaleSeen, actComplete }`
- `evaluateAct1Progress(hub, character)` после каждого возврата из спуска
- Директор получает `hub` для буста сцен акта
- Журнал: `act1_witness`, `act1_heretic`, `act1_hollow` при завершении
